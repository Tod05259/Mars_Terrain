## 1. 목적과 이번 승인 범위

Unitree **H1**이 지정한 Gusev 고지대 USD의 경사진 구간을 **MPM 변형 토양과 상호작용하며 두 발로 올라가는 정책**을 학습한다. 학습 rollout에서 MPM 입자의 위치·속도·응력 상태를 갱신하고, 토양 반력을 H1에 전달해야 한다. 강체 지형 학습 후 MPM에서 재생하는 것만으로는 목표 달성으로 판정하지 않는다.

이번 문서는 참고 자료, 재사용 범위, 구현 순서, 검증 기준을 승인받기 위한 계획이다. 현재 수행한 작업은 파일·소스·설치 메타데이터의 읽기 전용 조사와 이 문서 작성이다. 코드 이식, USD 복사·변환, 환경 설치, 시뮬레이션, 학습은 승인 후 시작한다.

사용자는 이 문서 전체를 검토한 뒤 **“workflow(2).md 승인”** 또는 수정 사항을 전달한다. 승인되면 아래 단계별 통과 조건을 확인하며 진행한다. 목표 지형 교체, MPM 학습 생략, 최종 성공 기준 완화가 필요하면 변경 근거를 먼저 제시한다.

### 참고 자료에서 확인한 핵심 제약

1. **MPM 전진 보행부터 확인해야 한다.** `50_walk_probe.py`에는 이전 등반 정책이 10회 모두 0 m 등반에 그쳤다는 기록이 있고, `51_eval_walk.py`에는 강체 지형과 모래의 명령 추종 격차가 기록되어 있다. 이는 참고 코드의 실험 기록이며 이번 환경에서 재현한 결과는 아니다.
2. **물성은 버전별로 달라졌다.** 현재 `07`의 highland 스케일은 `(friction=3.2, young_modulus=2.55, yield_pressure=1.7)`이다. 코드 주석의 지지력·안식각 보정 주장은 이번 재현의 출발점으로만 취급한다. 참조한 `mars_escape_env/CALIBRATION.md`는 조사한 두 저장소의 해당 위치에서 확인되지 않아 원 실험 조건을 추가 확인해야 한다.
3. **보정값을 무조건 상속하지 않는다.** 과거 작은 MPM 패치에서 나온 지지력·침하·탈출률이 정정되었다. 패치 폭, 토양 깊이, 입자 간격, 경계 조건, 강체 바닥 간섭을 함께 검증해야 한다. 준정적 시험의 해상도 수렴이 동적 보행 수렴까지 보장하지 않는다.
4. **기존 성공 판정도 수정 대상이다.** 과거 최대 전진 거리와 현재 서 있음만 조합하면 이전의 도약·미끄러짐을 성공으로 셀 수 있다. 목표 위치·지형 고도 상승·유효 보행·자세 유지를 같은 에피소드의 실제 상태로 확인한다.
5. **문서의 최신 API와 설치 API를 구분한다.** [Newton 공식 SolverImplicitMPM 문서](https://newton-physics.github.io/newton/latest/api/_generated/newton.solvers.SolverImplicitMPM.html)는 입자 상태 갱신, collider impulse, world 격리 기능을 설명한다. 이 문서는 `latest`이므로 로컬 1.2.1에서의 지원 근거로 사용하지 않는다. 실제 호출은 설치 소스로 확정한다.

## 4. 구현 구조와 초기 설정 제안

우선 경로는 **IsaacLab 실행 환경 + Newton H1/MPM 런타임 + RSL-RL PPO 어댑터**다. 현재 로컬 IsaacLab의 일반 velocity task에 MPM이 바로 연결된다고 가정하지 않는다. CAPSTONE의 최신 H1 런타임·벡터 환경에서 필요한 기능을 분리해 WORK 안에 구현한다.

```text
지정 USD → 참조/단위/변환 검증 → 실제 상향 경로와 지형 충돌 메시
                                      ↓
H1 강체 동역학 ← 토양 반력 ← MPM 토양 상태 갱신
      ↑                         ↑
   PD 관절 목표              발·지형 collider
      ↑                         ↑
PPO 행동 ← 관측/보상/종료 ← 환경 step 및 완전한 reset
```

| 항목 | 초기안과 확정 방법 |
|---|---|
| 중력 | `(0, 0, -3.721) m/s²`. 로봇과 토양에 동일하게 적용한다. |
| 로봇 | H1, 정책 행동 19차원 구조를 우선 검토. 실제 자산의 관절 이름·순서·기본 자세·토크 제한을 대조한다. |
| 제어 주기 | 기존 참고값 0.02 s(50 Hz), 강체 substep 4, MPM substep 2를 시작점으로 시간 수렴을 확인한다. |
| 관측 | 기존 H1 256차원 구성을 검토: 본체 속도·중력 방향·명령 12 + 관절/행동 57 + 높이 스캔 187. 순서, 단위, 좌표계, 정규화를 체크포인트와 대조한다. |
| MPM 재료 | `gusev_highland`의 현재 기본 물성 × 현재 보정 스케일. 층별 배율까지 적용한 최종 수치를 로그에 남긴다. 내부 마찰 계수와 발–토양 접촉 마찰을 구분한다. |
| 공간 해상도 | 입자 간격 12.5 mm를 후보로 두고 6.25 mm 등과 짧은 비교 시험. voxel 크기와 particles-per-cell의 관계도 기록한다. 성능 때문에 임의로 조악화한 결과를 최종 검증으로 쓰지 않는다. |
| 토양층 | 원본 DTM을 하부 지지면으로 두고 그 위에 변형 토양을 배치하는 모델을 우선 검토. 두께와 표면 기준을 명시하고, 관측·스폰·침하 계산에서 같은 표면을 사용한다. |
| MPM 영역 | H1을 추종하는 수평 투영 2 m × 2 m 이동 패치를 기본으로 사용한다. 영역 내부의 토양 변형을 유지하고 새로 진입하는 부분만 입자를 재배치한다. 지형 전체나 경로 전체를 MPM으로 채우지 않는다. |
| 반력 전달 | 참고 코드의 명시적 양방향 결합을 검증. impulse/시간 변환, 부호, 작용점, 토크, 한 제어 스텝 지연을 확인한다. |
| 수치 제한 | 참고 400 N/80 N·m 반력 제한, 입자 감쇠·속도 제한은 수치 안정화 설정이다. 포화 빈도와 제한 민감도를 보고하며 실제 로봇 사양으로 부르지 않는다. |
| 병렬 환경 | 1개로 검증 후 2 → 4 → 8개를 측정. 더 큰 개수는 메모리·처리량·격리 검증을 통과할 때만 사용한다. |
| 정책 초기화 | 호환되는 H1 보행 체크포인트가 있으면 초기화에 활용. 이력이 불명확한 탈출·등반 체크포인트는 비교군으로 분리한다. 이후 반드시 MPM rollout으로 PPO를 업데이트한다. |

설치 메타데이터 조사에서는 `_isaac_sim`이 `C:\isaacsim-6.0.1`을 가리키며 해당 Kit 환경에 Newton 1.2.1, Warp 1.13.0, RSL-RL 5.0.1, Torch 2.10.0+cu128이 보였다. 이는 **import·CUDA 실행 검증 결과가 아니다**. 다른 conda 환경과 패키지 버전이 다르고 CAPSTONE 최신 코드에는 더 새로운 Newton 좌표 레이아웃 관련 처리가 있어, 먼저 실행 Python을 고정한다. 기존 환경을 일괄 업그레이드하지 않는다.

### 4.1 H1 추종 2 m × 2 m 이동 MPM 패치

**기본 학습 방식은 로봇 주변에만 MPM 토양을 유지하는 이동 패치다.** 지정 USD의 지형 형상과 경로는 유지하며, MPM 물질점·격자는 H1 주변에서만 계산한다. MPM 물질점은 개별 모래알을 하나씩 재현하는 것이 아니라 토양 연속체의 상태를 저장하는 계산점이다.

- **영역과 중심:** 기본 크기는 world XY 수평 투영 2 m × 2 m이다. 경사면을 따른 실제 표면적과 구분한다. 로봇 위치를 추종하되 양발의 평균 XY 위치를 중심 후보로 우선 검증하여, 몸통이 경사 방향으로 기울 때도 지지발 주변 토양이 패치 경계에 걸리지 않게 한다. 로봇 yaw에 따라 사각 영역을 매번 회전시키지 않는다.
- **내부 상태 유지:** 창의 중심만 이동하고 내부에 남은 토양을 로봇과 함께 평행이동시키지 않는다. 내부 입자의 위치·속도·응력·소성 변형과 발자국은 계속 진화한다. 매 프레임 패치 전체를 초기화하지 않는다.
- **입자 재활용:** 고정된 입자 풀을 재사용한다. 패치를 떠난 기준 격자 열을 새 진입부로 재배치하고, 지정 USD의 해당 위치 높이와 토양 두께에 맞춰 층을 구성한다. 재배치된 입자만 속도·응력·변형 이력·지역 물성을 적절한 초기 상태로 복구한다. 현재 입자 위치만으로 개별 입자를 감싸 옮겨 층이 누락되지 않게 한다. 실제 격자 폭과 재활용 주기는 모두 정확히 2 m로 일치시켜 토양이 희석되거나 겹치지 않게 한다.
- **정착과 접촉 보호:** 양발과 다음 착지점이 영역 안에 들어오도록 여유 폭을 둔다. 새로 생성되는 토양이 발 아래 갑자기 나타나거나 지지발 아래 토양이 삭제되지 않게 한다. 새 진입부의 정착 과도현상과 경계 재배치 충격을 확인한다. 현재 코드의 창 밖 입자 되돌리기도 질량·운동량·에너지에 미치는 영향을 검증하며 그대로 물리 현상으로 간주하지 않는다. 강체 지형 충돌 메시는 이동 경로와 전체 패치를 계속 덮는다.
- **메모리 예산:** 일정한 두께와 해상도에서는 입자 수가 주로 4 m² 패치 체적에 의해 정해져 이동 거리와 함께 증가하지 않는다. 균일 입자 간격 12.5 mm, 수직 두께 0.20 m라면 약 409,600개, 0.30 m라면 약 614,400개/환경이라는 단순 체적 추산이 나온다. 실제 수는 배치·층 정의에 따라 달라지며 격자·solver 작업 메모리가 추가된다. 작은 면적이어도 환경 수를 바로 크게 잡지 않는다.
- **효율 비교:** 30 m × 30 m 전체를 동일 두께·간격으로 채운 가정과 비교하면 2 m × 2 m의 토양 체적·입자 수는 약 1/225이다. 이것은 면적에 따른 추산이며 225배 학습 속도 향상을 뜻하지 않는다. 강체 연산, 지형 충돌, 격자 구축과 PPO 비용을 포함한 실측 처리량으로 판단한다.
- **경계 검증:** 초기 시험에서 2 m × 2 m와 더 넓은 국소 패치(예: 3 m × 3 m)를 짧게 비교해 침하·슬립·반력 차이를 확인한다. 지형 전체 MPM은 비교 시험에도 요구하지 않는다. 발 접촉 영향 영역이 경계에 닿거나 토양이 옆으로 빠져 지지력이 달라지면 해당 조건을 유효한 학습 결과로 쓰지 않는다.
- **지나온 지형의 이력:** 기본안은 패치 밖 토양 이력을 폐기한다. 따라서 멀리 되돌아오면 이전 발자국이 복원되지 않으며, 장거리 토양 이동·사면 전체 붕괴를 재현하지 않는다. 이 제약을 결과에 명시하고 단방향 등반을 우선 평가한다. 왕복이나 재방문이 핵심인 과제로 확장되면 공간별 상태 저장이 필요하다.
- **동일한 학습·평가 조건:** 최종 학습과 평가는 같은 이동 패치·재활용 규칙을 사용한다. 평가 로그에 패치 중심, 발–경계 최소 거리, 재활용 입자 수, 새 진입부 토양 높이 오차, 재배치 직후 반력 변동을 추가한다.

CAPSTONE의 `terrain/scripts/07_h1_mars_newton.py`의 `recycle_particle_window()` 및 `terrain/scripts/26_escape_env_vec.py`의 `recycle_window_env()`가 재사용 후보다. 2026-09-19 읽기 전용 확인에서 기준 격자 위치를 이용한 입자 재활용 코드가 확인되었다. 새 H1 등반 환경에서의 성능·정확도는 아직 검증하지 않았다.

## 5. 승인 후 진행 순서와 통과 조건

### 단계 0 — 실행 환경과 출처 고정

- 승인된 작업 폴더에 필요한 소스·설정만 이식하고 원본 경로·커밋·해시를 기록한다.
- `LAB/isaaclab.bat -p`를 우선 사용해 Python, Newton, Warp, Torch, RSL-RL, USD import와 CUDA를 확인한다. Windows 배치 런처는 저장소의 `isaaclab.sh -p`에 대응한다.
- 설치 API, 관절 target 레이아웃, MuJoCo solver·MPM state·PPO 인터페이스를 최소 실행으로 확인한다.
- H1 자산과 초기 정책의 실제 경로·해시·구조를 확인한다. 다운로드가 필요하면 WORK 내부 저장 경로를 사용한다.
- 로컬 Newton 캐시에 H1 자산이 있으므로 우선 의존 자산과 함께 재사용한다. CAPSTONE 코드의 기본 사전학습 checkpoint 경로는 현재 확인되지 않았고 기존 등반·하강 checkpoint 후보만 확인되어, 초기 정책의 적합성 검증이 필요하다.
- 설치 소스에서 확인한 `NEWTON_CACHE_PATH`, `WARP_CACHE_PATH`를 WORK 내부로 지정하고, Python bytecode·임시파일·Kit 로그도 같은 작업 범위로 제한한다.
- **통과 조건:** 실제 실행 환경이 기록되고, 핵심 import·CUDA와 최소 H1/MPM 생성이 정상이며 출력·캐시 경로가 허용 범위 안이다.

### 단계 1 — 지정 USD와 등반 경로 확정

- USD의 `metersPerUnit`, up axis, prim 변환, terrain mesh, face 방향, collision, rock reference와 material을 점검한다.
- USD와 필요한 종속 자산을 WORK에 복사한다. 상대 참조 관계를 보존하거나 복사본의 참조만 수정하고, 누락 자산 목록과 복사 전후 지형 일치를 검증한다.
- world 좌표의 높이·경사·경사 방향을 계산하고, 경계·급격한 단차·바위·MPM 영역 여유를 고려해 시작점과 목표점을 정한다. 높이 샘플링과 실제 삼각형 충돌 표면의 일치도 확인한다.
- **우선 범위:** 30 m 지형 안의 하나의 유효한 오르막 구간에서 학습과 평가를 완성한다. 30 m 전체 횡단은 이번 초기 완료 기준으로 가정하지 않는다.
- **통과 조건:** 좌표, 경로 길이, 누적/순 고도 상승, 경사 분포, 진행 방향, 경계 여유가 `route.json`과 지형 그림으로 고정된다. 현재 문서에는 임의 좌표·각도를 넣지 않는다.

### 단계 2 — 경사 MPM 물리 검증

- 로봇 없이 정착시켜 토양 손실·자발 흐름·입자 속도·유효 두께를 기록한다. 완전히 흘러 사라지는 토양층으로 보행 학습을 시작하지 않는다.
- 짧은 압입·전단/안식각 확인과 H1 정지 지지 시험으로 토양이 발을 실제로 지지하는지 확인한다.
- 2 m × 2 m 이동 패치를 기준으로 더 넓은 국소 패치와 짧게 비교하고, 토양 깊이·입자 간격·시간 간격에 따른 침하·지지력·슬립 민감도를 확인한다. 이동 중 입자 재활용 전후의 지지 연속성도 검증한다. 참고 문서의 1.6 m 수렴 결과를 등반 경로에 그대로 적용하지 않는다.
- 강체 바닥 접촉, 토양 상부와 중복된 강체 충돌, 숨은 지지면, MPM 반력의 중복 적용을 점검한다. 바위는 원본에 따른 별도 접촉으로 기록한다.
- 발뿐 아니라 정강이·무릎·몸통 등 비발 부위의 충돌 처리를 확인하여 몸이 지면을 관통한 상태를 안정적인 보행으로 오인하지 않게 한다.
- **통과 조건:** NaN·발사·관통·지속적인 바닥 지지로 인한 가짜 안정이 없고, 물성·경계·해상도 선택의 근거가 남는다. 경사면의 자연스러운 흐름은 실패와 구분해 기록한다.

### 단계 3 — 학습 환경과 reset 검증

- `step`, `reset`, 관측, 보상, 종료·시간제한, checkpoint 저장·재개 인터페이스를 구현한다.
- reset은 관절·본체 상태, 양쪽 강체 state buffer, 입자 위치·속도·변형/소성/응력, 물성, 토양 반력, solver 내부 상태, 이전 행동·관측 이력을 모두 다룬다. collider의 이전 pose/history도 동기화해 순간이동에 의한 가짜 충격을 방지한다. 기존 매몰 스냅샷 대신 이번 경로와 정상 토양의 초기 상태를 만든다.
- 일부 환경 reset이 다른 환경의 토양·로봇·누적 지표에 영향을 주지 않는지 비교한다. shared grid를 쓰면 공간 간격과 collider 격리도 검증한다.
- 단일 환경과 병렬 환경에 같은 초기 상태·행동을 주고 관측·보상·종료 및 로봇·토양 궤적을 비교한다. 공간 offset을 제거한 좌표에서 수치 허용오차를 적용하고 동등성을 확인한다.
- 짧은 PPO 실행에서 실제 MPM step 수, 입자 상태 변화, 토양 반력, gradient·정책 파라미터 변화, 저장 후 재개를 확인한다.
- **통과 조건:** MPM이 켜진 학습 rollout으로 정책이 업데이트되고, 반복 reset과 부분 reset 후에도 상태가 정상이다. 구현 오류 때문에 학습이 멈춘 것을 성능 문제로 판단하지 않는다.

### 단계 4 — MPM 기본 보행과 경사 커리큘럼

1. H1 초기 정책의 강체/MPM 전진을 동일 명령으로 비교해 기준선을 기록한다. 강체 조건은 진단 비교군이다.
2. 목표 지역 물성을 사용한 MPM 환경에서 기본 정지·전진·방향 유지부터 학습한다. 지정 지형의 완만한 구간을 우선 사용하며, 단순 평면 진단은 별도 조건으로 표시한다.
3. 출발 자세와 토양 정착 조건을 안정화한 뒤 실제 지정 지형에서 짧은 상향 구간 → 긴 구간 → 더 가파른 유효 구간 순으로 확장한다. 최종 평가 지형을 회전·평탄화해 난도를 낮추지 않는다.
4. 기본 전진 통과안: 0.3 m/s 명령으로 8 s 동안 명령 거리의 50% 이상 유효 전진, 전도 없음, 지속적 제자리 회전·횡이동 없음. 이후 등반 학습으로 진행한다.
5. 보상은 경로 진행, 목표 방향/속도 추종, 균형·유효 발 지지, 토크·행동 변화·접촉 중 슬립을 사용한다. 수직 몸통 이동만으로 고도 상승을 보상하지 않는다. 왕복으로 보상을 반복 획득하거나 기어가기·토양에 밀려 이동하기로 등반을 대체하지 못하게 평가한다.
6. 첫 학습은 짧은 구간으로 손실·보상·물리 지표를 확인하고, 이후 checkpoint 단위로 연장한다. 처리량을 측정한 뒤 학습량과 예상 시간을 산정하며, 측정 전 완료 시간이나 성공을 약속하지 않는다.

### 단계 5 — 분리 평가와 재현 산출물

- 학습에 사용하지 않은 seed·출발점 변동으로 고정 정책을 평가한다. 정상 highland 물성을 기본으로 하고 제한된 물성 변동은 별도 강건성 평가로 구분한다.
- 초기 정책과 MPM 학습 정책을 동일 경로·명령·물리 설정으로 비교한다. 필요 시 MPM off 비교도 진단 목적으로만 수행한다.
- 성공과 실패 모두 기록하며, 성공 영상만으로 성공률을 제시하지 않는다. 수치 발산·토양 소실 에피소드도 전체 시도 수와 실패 사유에 포함한다.
- **통과 조건:** 아래 성공 기준에 따른 에피소드별 결과, 정책, 재실행 설정, 전체 평가 요약이 함께 제공된다.

## 6. 성공 기준 제안과 보고 지표

아래 수치는 **사용자가 이번 문서에서 검토할 초기 목표안**이며 달성했다고 주장하는 값이 아니다. 단계 1에서 실제 경로가 이 조건을 만족하는지 검증하고, 불가능하면 기준을 조용히 낮추지 않고 근거를 보고한다.

| 항목 | 제안 기준 |
|---|---|
| 경로 | 지정 USD의 실제 오르막에서 수평 경로 길이 3 m 이상, 목표 지형 높이가 출발 지형보다 0.3 m 이상 높음 |
| 제한 시간 | 에피소드 30 s 이내 목표 구간 도달 |
| 도달 판정 | 목표점 수평 거리 0.3 m 이내, 경로 진행률 95% 이상, 현재 위치의 지형 고도 상승 0.3 m 이상을 함께 만족 |
| 유효 보행 | 이동 중 양발의 지지·스윙 교대와 방향성 있는 전진 확인. 전도·기어가기·지속적 도약/발사·끌려감·MPM 영역 이탈로 얻은 이동은 성공에서 제외 |
| 최종 유지 | 목표 도달 후 1 s 동안 유효 발 지지와 정상 몸통 높이·자세 유지 |
| 반복성 | 평가 seed 3개 × 10회 = 30 에피소드. 전체 성공률 80% 이상을 초기 목표로 두고 seed별 결과도 보고 |
| 물리 유효성 | MPM 반력·입자 상태가 실제 변하며, 수치 제한 포화·강체 바닥 의존이 결과를 지배하지 않음. 접촉·자세·슬립 임계값은 진단 후 학습 결과를 보기 전에 설정 파일로 고정 |

기록 지표: 상향 경로 진행거리, 현재 지형 고도 상승, 도달 시간, 전도율, 횡방향 이탈, 명령 추종 오차, 접촉 중 발의 접선방향 슬립, 발 주변 국소 토양면 대비 침하, 지지발 교대, 비발 접촉, 강체 바닥 접촉, 반력 제한 포화율, 입자 속도 제한 포화율, 입자 질량/영역 이탈, NaN/수치 발산, 환경별 처리량, RAM/VRAM, 총 학습 step과 실제 소요 시간.

경사면 전체 입자 높이의 백분위수를 발의 침하 기준으로 쓰지 않는다. 발 주변 국소 표면·법선과 기준 토양면을 사용해 경사로 인한 높이 차이를 침하와 구분한다. 높이 스캔이 원본 DTM만 읽는다면 이를 명시하고, 실제 변형 토양 관측과 혼동하지 않는다.

## 7. 예정 산출물과 실행 방식

아래에서 현재 존재하는 신규 산출물은 **`workflow(2).md` 하나**다. 나머지는 승인 후 생성할 구조다.

```text
Mars_Terrain/h1_mars_mpm_uphill/
├── workflow(2).md
├── README.md                     # 검증된 설치·학습·평가·재개 명령
├── references/source_manifest.json
├── assets/                       # 지정 USD, 종속 자산, H1 자산
├── configs/                      # 경로·물성·로봇·PPO·평가 고정 설정
├── src/                          # 지형, H1/MPM 환경, 학습 어댑터
├── scripts/                      # 사전 점검·지형 분석·학습·평가
├── tests/                        # 관절 매핑·좌표계·reset·성공 판정 검증
├── reports/                      # 환경 점검·지형 그림·물리 검증·평가 CSV/JSON
├── runs/                         # 설정 사본·로그·checkpoint·영상
└── .work/                        # 실행 임시파일·캐시
```

최종 CLI는 `--terrain_usd`, `--num_envs`, `--checkpoint`처럼 snake_case로 만든다. 아래는 **아직 구현되지 않은 예정 진입점**이며 지금 실행하는 명령이 아니다. 실제 지원 옵션과 검증된 명령은 구현 후 README에 확정한다.

```powershell
# C:\IsaacLab-3.0.0-beta2 에서, 승인 후 구현된 스크립트를 실행하는 형태
.\isaaclab.bat -p C:\Users\2hj05\repos\Mars_Terrain\h1_mars_mpm_uphill\scripts\preflight.py
.\isaaclab.bat -p C:\Users\2hj05\repos\Mars_Terrain\h1_mars_mpm_uphill\scripts\train.py --num_envs 1
.\isaaclab.bat -p C:\Users\2hj05\repos\Mars_Terrain\h1_mars_mpm_uphill\scripts\evaluate.py --checkpoint <검증할_정책>
```

물리 정확성에 필요한 테스트와 짧은 실행부터 수행한다. 버그 회귀 테스트를 추가하면 수정 전 실패·수정 후 통과를 확인한다. IsaacLab 패키지를 변경할 필요가 생기면 해당 패키지 changelog fragment와 공개 API 문서를 갱신하며, 커밋·푸시 전 저장소 지침의 전체 pre-commit 검사를 수행한다. 이번 문서 작성은 패키지 수정이나 코드 리뷰에 해당하지 않으며 formatter·시뮬레이션을 실행하지 않았다.
